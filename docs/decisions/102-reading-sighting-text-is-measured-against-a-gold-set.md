# 102 — Reading sighting text is measured against a checked-in gold set

**Status:** accepted · **Decided:** 2026-10-31, by Peter · **Work:** bd `salish-2otb`; feeds `salish-26fp` (a model reads sighting text) and `salish-2ua9` (behaviour tags) · **Builds on:** [061](061-ingest-and-derivation-move-into-the-build.md) (the text extractions run in the build as twins of Postgres's)

## Context

The build reads a sighting's free text in two places, both regular expressions in [`scripts/read-path/derive/extract.sql`](../../scripts/read-path/derive/extract.sql): a travel direction, and the catalogue codes it names, which become the occurrence's identifier candidates and the archive's `unvalidatedIdentifiers`. The client has sibling regexes for ecotype and pod. They were ported from Postgres as twins, quirks included, and tested as twins: the question the tests ask is whether DuckDB answers what Postgres answered, not whether either reads the text right.

Peter asked how much better the project could read text, by patched regexes, by a token grammar over the register's names, or by a Claude model given the project's context. Over the year of Maplify killer whale reports to 2026-10-30 (2,698 with text), the macros find a code in 42% and a direction in 69%. Reading a sample by hand showed where they fail: directions written `NB`, `SB` or `NE bound` (5% of reports); a code written without its letter after a slash or comma, `T36/36Bs` (3%); an animal the text excludes, `T46s (-D)`, listed as present (2%); a report that names only a pod (17%); a change of direction where the first compass word wins; a bearing from a landmark, *north of Alki*, read as a direction. Precision on the codes found is close to perfect: of 130 distinct codes extracted in the year, 117 resolve against the catalogue, and most of the rest are 2026 designations the catalogue lacks.

Cost does not decide between the approaches. Peter's Claude subscription covers far more model usage than reading every report would take. What a model step would add is a dependency: the build would run on his personal credentials, and the project breaks if he cancels. And none of the three approaches could be judged, because nothing recorded what the texts say.

## Decision

**A gold set of 200 Maplify reports, read by hand, is checked in at [`scripts/read-path/fixtures/gold/`](../../scripts/read-path/fixtures/gold/README.md), and any change to how the build reads text is measured against it.** The rows are 100 random killer whale reports, 40 random reports of other species and 60 drawn by filters for the patterns the regexes get wrong, so the random strata estimate the corpus and the hard strata say how a reading does on each pattern; the twelve rows the filters matched by accident are kept, in a stratum of their own, so they count for no pattern. Each row records what the text says: codes present, absent and hedged, pods, ecotype, nicknames, the reporter's certainty, the direction now and before, counts, a calf, behaviour words, places, who identified, and whether the text is a later edit. The labels are the truth; the extraction's output is not stored.

**A test pins, by stratum, which rows the current macros get wrong** ([`derive/extract-gold.test.ts`](../../scripts/read-path/derive/extract-gold.test.ts)). A change to the macros moves rows between right and wrong, and that movement is reviewed in the pull request as a twin fixture's rows are ([twins/README.md](../../scripts/read-path/fixtures/twins/README.md)). Today the macros get the direction right in 94 of the 100 random killer whale reports and the code list right in 94; on reports with an exclusion the code list is right in 7 of 15, on codes without their letter 0 of 13, on abbreviated directions 0 of 5.

**The deterministic extraction stays the thing the build depends on.** A reading by a model, if built, is an optional input the build caches by the text's hash and can do without, so that a lapsed subscription or an API outage degrades the site to today's reading rather than stopping the build (Stelis's rule that the same input builds the same bytes also needs the cache). Which fields a model should read, and whether it beats a token grammar on them, is what the gold set is for; the expectation recorded here is that codes, pods and directions stay deterministic and a model earns its place on the semantic layer: exclusions, hedges, changes of direction, counts, behaviour and a summary sentence.

## Rejected

- **Patching the regexes first, then measuring:** the misses are patterns and most are cheap to fix, but a fix changes the archive's `unvalidatedIdentifiers` with nothing to say whether it helped. The measure comes first.
- **Calling the API to try a model on the sample now:** whether Maplify comments may be sent to the API is a rights question `salish-26fp` flags and the rights policy does not answer. The sample was read by hand instead.
- **Keeping the gold set only in the Google Sheet where it was reviewed:** the sheet is where a person reads and edits it, but a test cannot reach it, and the fixture must change by pull request as the catalogue does ([064](064-the-catalogue-is-checked-in-data.md)).
- **Storing the macros' current output in the fixture beside the labels:** the labels are the truth and the output is a measurement; pinning the output row by row would make every improvement a 200-row edit. The test pins only the rows got wrong.
